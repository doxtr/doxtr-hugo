## [0.1.0] - 2026-10-18

First public release. The extension is feature complete against the
implementation guide.

### Added

- **Hugo builder** — registers a `hugo` builder (`sphinx-build -b hugo`, and the
  `make hugo` target generated by `sphinx-quickstart`) that walks the resolved
  doctree and emits one Markdown file per document plus co-located assets, laid
  out as a buildable Hugo site.
- **Content translation** (`HugoTranslator`) — headings, paragraphs, inline
  markup (emphasis/strong/literal), bullet and enumerated lists (nested), and
  fenced code blocks. The page's leading top-level title is carried by the
  `title` front matter and omitted from the body by default
  (`doxtr_hugo_title_heading = "frontmatter"`) so a theme that renders `.Title`
  does not show it twice; set `"body"` to keep the legacy in-body `# Title`.
- **Tables** — GFM pipe tables by default, with a raw-HTML fallback for cells
  that span rows/columns; `doxtr_hugo_tables = "html"` forces raw-HTML tables.
- **Admonitions** — typed directives (note, warning, tip, caution, danger,
  error, hint, important, attention, seealso) and generic `.. admonition::`
  titles, emitted as a Hugo shortcode by default or raw HTML via
  `doxtr_hugo_admonitions = "html"`.
- **Links / cross-references** — external links to CommonMark, `:doc:`/`:ref:`
  to Hugo `relref` by default (or plain relative paths via
  `doxtr_hugo_link_style = "relative"`), preserving anchor fragments.
- **Front matter** (`frontmatter.py`) — TOML by default (`+++` delimiters),
  with YAML and JSON selectable via `doxtr_hugo_front_matter`; deterministic
  key order and reserved-key routing into a `[params]` namespace.
- **toctree / site model** (`toctree.py`) — toctree to Hugo sections with
  deterministic per-parent weights, branch vs. leaf page classification, and
  orphan handling.
- **Site skeleton** (`site_skeleton.py`) — emits `hugo.toml`, section
  `_index.md` files, and a minimal `layouts/` plus admonition/figure
  shortcodes; `doxtr_hugo_emit_skeleton = "content-only"` omits the skeleton.
- **Slug / path mapping** (`slug.py`) — docname to Hugo path/slug using Hugo
  `urlize` semantics and pretty URLs; supports leaf-bundle and flat bundle
  modes via `doxtr_hugo_bundle_mode`.
- **Diagrams** (`diagrams.py`) — PlantUML, Graphviz, Mermaid, d2 (`doxtr_d2`),
  and sphinx_diagrams (the `diagrams` Python library, PNG-only) detection and
  render-to-file, content-addressed asset filenames, with graceful degradation
  (`doxtr_hugo_on_missing_backend`: `warn-passthrough`, `warn-skip`, `error`)
  when a backend binary is absent. Custom backends register via the public
  `doxtr_hugo.register_backend` seam.
- **Image policy** (`image_policy.py`) — SVG-preferred / PNG-fallback format
  decision honoring `doxtr_hugo_image_format`, `doxtr_hugo_raster_fallback`,
  and `doxtr_hugo_process_images`.
- **Math rendering** (`math_render.py`) — PNG by default (zero extra binary via
  matplotlib mathtext), with `mathjax` and `mathml-passthrough` opt-in via
  `doxtr_hugo_math`.
- **Assets** (`assets.py`) — content-hashed, co-located assets with an
  append-only `.doxtr-hugo-manifest.json` manifest for deterministic, cache-busting
  output.
- **Configuration surface** (`config_defaults.py`) — all `doxtr_hugo_*` config
  values with documented defaults.
- **Typed package** — ships a PEP 561 `py.typed` marker so downstream projects
  pick up the package's inline type hints under mypy/pyright.
- **Theme configuration** (`theme_support.py`) — configure a Hugo theme in the
  Sphinx `conf.py` and emit a complete, version-controllable, serve-ready Hugo
  site. `doxtr_hugo_theme` selects a shipped profile (`archie`, `hugo-terminal`,
  `hyde`, `risotto`, `notepadium`, `hugo-book`, `docsy`) or any theme name; the
  final `hugo.toml` is a deep-merge of core defaults + the profile's config
  fragment + `doxtr_hugo_theme_config` (user wins). A `README-hugo.md` documents
  the one-time theme toolchain steps (Hugo Module fetch, Dart Sass, npm) — the
  extension documents them, never executes them. A confdir-relative sidecar
  overlay (`doxtr_hugo_theme_overlay_dir`, default `.doxtr/hugo/`) is copied
  verbatim into the output as a declarative escape hatch (auto-excluded from
  Sphinx's doc scan), and an opt-in `doxtr_hugo_theme_hook` runs user project
  code last for programmatic post-processing. `doxtr_hugo_theme_source` controls
  how the theme is obtained (Hugo module by default; submodule/vendor/path).

- **Invisible / build-time-only nodes** — RST comments (`.. a comment`),
  substitution *definitions* (`.. |name| replace:: ...`), docutils system
  messages, `.. meta::` metadata, and transform `pending` placeholders are
  suppressed in full: neither the construct nor its text is emitted, matching
  the standard docutils/Sphinx HTML writer. (Previously such text could leak
  into the rendered page.) Resolved substitution *usages* still render; this
  only drops the invisible definition/plumbing nodes.

### Fixed

- **Hugo section hierarchy now follows the authored toctree, not the source
  directory layout.** The emitted ``content/`` tree, pretty URLs, section
  ``_index.md`` files, and ``{{< relref >}}`` targets are all derived from each
  document's ``.. toctree::`` ancestor chain, so the Hugo navigation hierarchy
  is identical to the Sphinx (alabaster) reading hierarchy
  (e.g. ``Extensions/Doto/Studies/High School/Chemistry``). Two Sphinx
  directory-index conventions are collapsed consistently so a section owns its
  folder instead of a phantom child directory:

  - ``foo/index.rst`` → ``content/foo/_index.md`` (not
    ``content/foo/index/_index.md``);
  - ``foo/foo.rst`` (the landing-page convention) → ``content/foo/_index.md``
    (not ``content/foo/foo/_index.md``).

  Previously each document mapped 1:1 from its *source path*, so a landing page
  that included a sibling-folder section in its toctree (e.g. a ``doto/doto``
  page including ``studies/index``) emitted them as unrelated sibling
  directories, and the deep subject hierarchy did not nest correctly under
  themes like docsy/hugo-book.

- **Sibling page ordering follows the toctree.** Every non-root page (leaf and
  branch) now carries its deterministic toctree ``weight`` in front matter, so
  a section's pages render in the authored ``.. toctree::`` order instead of
  Hugo's default alphabetical (title/filename) order. Previously only branch
  sections got a weight, so leaf pages sorted alphabetically (e.g. "Colored
  roadmap" ahead of "Getting started").

- **No duplicate child listing under section-listing themes.** A section page
  whose body already renders its toctree children as an in-page list now emits
  ``no_list = true`` so themes that auto-append a child index (e.g. docsy's
  ``section-index`` partial) do not render the listing twice. Leaf pages and
  empty skeleton sections are unaffected, as are themes that ignore the flag
  (hugo-book, the bare skeleton).

- **Block content inside a definition list.** A definition whose body contains
  a code block (or other block construct) now emits the Goldmark ``: `` marker
  on the first line only and indents continuation lines, instead of prefixing
  every line with ``: ``. The old behaviour split a fenced code block into
  per-line definitions and rendered the fences empty (the garbled "Literal
  Blocks" example under Basics → Text Formatting).

- **Inline code containing backticks, and literal backticks in prose.**
  ``visit_literal`` now picks a backtick fence longer than any run inside the
  content (space-padded when it starts/ends with a backtick), so an inline
  literal like ``` ``this text is code`` ``` renders its backticks verbatim
  instead of mis-closing the span. Literal backticks (and backslashes) in
  running prose are backslash-escaped so an escaped RST ``\``\`` no longer
  opens a stray inline code span that swallows the following text.

- **Deeply nested lists.** A nested list now indents to the **content column**
  of its parent list item (past that item's marker) instead of a fixed two
  spaces per depth. An ordered marker is wider than a bullet (``1. `` is three
  columns, ``- `` is two), so the old fixed indent left a third level only two
  spaces deeper than the second — CommonMark/Goldmark then read the deepest
  items as siblings and the third level collapsed into the second. Lists now
  nest to full depth (the "Nested Lists" example under Basics → Lists).

### Testing & CI

- Unit test suite (`tests/`) with coverage gated at ≥ 75%.
- Integration harness (`test_harness/`) running a real `sphinx-build -b hugo`
  followed by a real `hugo` build, asserting emitted formats via magic-byte
  sniffing and skipping (never silently passing) when Hugo or a backend binary
  is absent.
- Multi-theme render matrix (guide §7.2a) across pinned Hugo themes.
- CI workflows: `test.yml` (package build, `pytest` with coverage), and
  `test-harness.yml` (pinned Hugo + pinned vendored themes).
- `publish.yml` — build and publish to PyPI via trusted publishing on a
  GitHub release.
